### 链表特性与数据结构的意义
1.  **链表的效率特点**
    链表这类线性表天生只适合存储数据，查找效率很低，这是链式存储的结构本身决定的，没办法实现高效查找。
    但双向链表**单纯的插入、删除操作本身是O(1)**的——因为能直接通过节点拿到前后节点，不需要遍历。很多人会把“查找位置的O(N)”算到链表头上，但查找（find）本身不是链表实现的功能，这部分的耗时不该算在链表插入删除的头上。

2.  **为什么要学数据结构**
    有同学觉得学基础数据结构枯燥、没用，老师强调：上手很快就能做的花里胡哨的内容都没什么含金量，想做深入的、有技术含量的开发，必须打牢基础。
    写程序本质就是管理数据：
    - 内存里的数据，基本都靠数据结构来管理；
    - 磁盘上的数据（文件、数据库），数据库的底层核心也是B树，还会涉及哈希相关知识；
    - 远端服务器的数据，则需要通过网络访问获取。
    这也是计算机专业必开数据结构课的原因。数据库是单独的学科，需要学习SQL语句，后面的MySQL课程会详细讲解。

### list 容器的常用接口讲解
老师表示链表核心内容已经讲完，剩下的操作接口重要性稍低，部分设计甚至有些冗余。

1.  **reverse 逆置**
    list自带了reverse逆置接口，但老师认为这个接口设计得很冗余、没必要——因为算法库的reverse函数也能完成逆置，list支持双向迭代器，完全可以用通用算法。这个接口属于早期发展中设计考虑不全留下的内容。

2.  **sort 排序**
    list自己单独实现了sort接口，**原因是标准算法库的sort要求随机迭代器，链表的双向迭代器不满足要求，用不了通用sort**。list自带的sort底层实现比较复杂，默认按升序排序。
    - 想排降序需要用到**仿函数**：升序对应`less`，降序对应`greater`，它们都是类模板，标准库已经提供，不用自己写。
    - 传参的时候推荐写**匿名对象**（比如`greater<int>()`），比单独定义有名对象更简洁方便。
    仿函数的底层原理暂时不展开，后面讲栈和队列、优先级队列（底层是堆）的时候，会结合比较逻辑详细讲解。

3.  **merge 链表合并**
    用来合并两个链表，**前提是两个链表都必须是有序的**。
    合并逻辑就是依次取两个链表中更小的元素尾插，最终把第二个链表的所有节点都转移到第一个链表里；合并完成后，第二个链表就空了，是节点的直接转移，不是数据拷贝。
    补充：调试的监视窗口会把链表像数组一样展示内容，只是为了方便调试，链表底层依然是链式存储，不是数组。
    老师补充：这个接口实际开发中用得也不多。

4.  **unique 去重**
    作用是删除链表中的重复元素，相同值只保留一个。
    - **前提要求：数据必须有序**。它的逻辑默认相同的值是挨在一起的，如果数据无序，就会出现重复元素删不干净的情况。
    - 底层是双指针思路：遍历的时候如果后一个值和当前值相等，就一直往后走，直到遇到不同的值，再把中间重复的节点都删掉，只保留第一个；整体时间复杂度是O(N)。
    去重本身不耗时，耗时的是排序步骤。不排序也能去重，但效率会非常低，所以常规做法都是先排序再去重。后续要学的map、set容器也能实现去重，后面再展开讲解。

5.  **remove 按值删除**
    和erase不同：erase是传入迭代器，删除指定位置的元素；remove是传入一个值，遍历链表找到对应值就删除，没找到也不会报错。
    还有带条件删除的`remove_if`（比如删除所有偶数），也会用到仿函数，后面再展开讲解。

## 1，list介绍：
1、list 的底层结构

- `list` 底层采用 **带头双向循环链表** 实现。
2、list 的构造方式

`list` 的构造方式与前面学习过的 `vector`、`string` 基本一致，都是 STL 容器统一的设计风格，因此学习起来并不陌生。

| 构造方式 | 说明 | 示例 |
| :--- | :--- | :--- |
| 默认构造 | 创建一个空链表 | `list<int> lt;` |
| 指定元素个数 | 创建 n 个元素，每个元素为默认值 | `list<int> lt(10);` |
| 指定元素个数和值 | 创建 n 个值为 val 的元素 | `list<int> lt(10, 1);` |
| 区间构造 | 用一段迭代器区间构造 | `list<int> lt(v.begin(), v.end());` |
| 拷贝构造 | 用已有 list 创建新对象 | `list<int> lt2(lt1);` |
| 移动构造（C++11） | 转移资源，提高效率 | `list<int> lt2(std::move(lt1));` |
| 初始化列表构造（C++11） | 使用 `{}` 初始化 | `list<int> lt{1,2,3,4};` |

## 2、为什么 list 不支持 `operator[]`

`vector` 由于采用连续存储，可以通过地址计算实现随机访问，因此支持：`operator[]`
时间复杂度为 **O(1)**。

而 `list` 的节点分散在内存各处，访问第 `i` 个元素必须沿着链表逐个遍历，因此时间复杂度为 **O(N)**。

为了避免用户误以为 `[]` 也是高效操作，STL 并没有为 `list` 提供 `operator[]`。

---

### 3、list 的访问方式

由于不能随机访问，`list` 主要通过：

- `front()`、`back()`
- 迭代器（Iterator）
- 范围 `for`来访问元素。

最常见的遍历方式：

```cpp
for (auto e : lt)
{
    cout << e << " ";
}
```

或者：

```cpp
for (auto it = lt.begin(); it != lt.end(); ++it)
{
    cout << *it << " ";
}
```

# 我认为最好的实现路线（推荐）

按照下面这个顺序，几乎不会走弯路：

| 顺序 | 接口                             |  推荐指数 | 原因                      |
| -- | ------------------------------ | :---: | ----------------------- |
| ①  | `list_node()`                  | ⭐⭐⭐⭐⭐ | 节点基础                    |
| ②  | `list_iterator()`              | ⭐⭐⭐⭐⭐ | 迭代器基础                   |
| ③  | `operator*()`                  | ⭐⭐⭐⭐⭐ | 访问数据                    |
| ④  | `operator++()`                 | ⭐⭐⭐⭐⭐ | 前向遍历                    |
| ⑤  | `operator--()`                 | ⭐⭐⭐⭐⭐ | 后向遍历                    |
| ⑥  | `operator!=()` / `==()`        | ⭐⭐⭐⭐⭐ | 比较迭代器                   |
| ⑦  | `list()`                       | ⭐⭐⭐⭐⭐ | 建立哨兵节点                  |
| ⑧  | `begin()` / `end()`            | ⭐⭐⭐⭐⭐ | 遍历入口                    |
| ⑨  | `size()` / `empty()`           | ⭐⭐⭐⭐⭐ | 状态接口                    |
| ⑩  | `insert()`                     | ⭐⭐⭐⭐⭐ | **整个 `list` 最核心接口**     |
| ⑪  | `push_back()` / `push_front()` | ⭐⭐⭐⭐⭐ | 基于 `insert()`，几乎一行实现    |
| ⑫  | `erase()`                      | ⭐⭐⭐⭐⭐ | **第二核心接口**              |

# 精华
先编写一个通用的 list_iterator<T, Ref, Ptr> 模板，把普通迭代器和常量迭代器唯一不同的地方（引用类型和指针类型）抽象成模板参数。编译器在实例化时，根据不同的模板参数分别生成 list_iterator<T, T&, T*> 和 list_iterator<T, const T&, const T*> 两个具体类型。最后再用 typedef（或 using）给这两个具体类型分别起名为 iterator 和 const_iterator，方便使用。
